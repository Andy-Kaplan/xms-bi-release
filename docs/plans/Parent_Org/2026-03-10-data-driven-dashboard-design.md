# Data-Driven Command Centre — Design

## Problem
Dashboard HTML and markdown todo files maintained independently, leading to drift and double work.

## Solution
Embed a single `DATA` object in `dashboard.html`. All five sections (upcoming, blocked, work todos, business todos, projects) render from this data via JS. Claude Code is the editor — no separate markdown files needed.

## Data Model
```json
{
  "upcoming": [
    { "id": "...", "date": "WED 11", "soon": true, "text": "...", "detail": "...", "done": false }
  ],
  "blocked": [
    { "id": "...", "icon": "...", "who": "Ian", "text": "...", "why": "...", "done": false }
  ],
  "workTodos": [
    { "id": "...", "text": "...", "meta": "...", "tags": ["Demo Wed"], "group": "in-progress", "done": false,
      "children": [{ "id": "...", "text": "...", "done": false }]
    }
  ],
  "businessTodos": [
    { "id": "...", "text": "...", "meta": "...", "tags": [], "group": "up-next", "done": false }
  ],
  "projects": [
    { "name": "...", "status": "hot|active|planning", "tasks": ["..."], "note": "..." }
  ]
}
```

## Rendering
- All section HTML generated by JS from DATA on page load
- Items with `done: true` are hidden
- Clicking checkboxes/dismiss buttons hides items visually (ephemeral — refresh resets)
- Real state updated by Claude Code editing the DATA block
- Counts auto-calculate from visible items

## Editing Workflow
- User tells Claude Code what changed
- Claude Code parses and updates the DATA block in dashboard.html

## Deletions
- `todos/work.md`
- `todos/business.md`
- `todos/` directory
