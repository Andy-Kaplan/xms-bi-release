  1. **Never filter `BOTTOM_LEVEL_NAME = 'Product'`** — it is `'Product'` for Growyze but `'BOTTOM'` for Mews/NCRAloha, so it silently drops every POS product. (`D_PRODUCT` also holds only leaf rows for Growyze — there are no `Category` rows, so a check filtering for them is vacuously empty.)
  2. **Category grain is `COALESCE(TOP_MICROSERVICE_NAME, TOP_NAME)`.** The correct level differs per source: Mews `TOP` = 12 real categories while its `MIDDLE_1` = product families (Peroni, Pinot Grigio); NCRAloha `TOP` = Food/Drinks (coarse) while `MIDDLE_1` = Mains/Cocktails/…; Growyze `TOP` ≡ `MIDDLE_1`. **Keep the `ProductCategories` entry in `FilterDefinitions` on the same grain as the `GROUP BY`** — they diverged once and picking a category blanked both KPI cards beside a populated pie.
  3. **Always `CAST(ORDER_DATE AS DATE)` on `CALENDAR` joins** — POS sources carry times; Growyze lands at midnight, which is why this was latent.
  4. **Set `ParameterMappings = N'{"StartDate":"C.[DATE]","EndDate":"C.[DATE]"}'`.** `BuildDynamicWhereClause` derives its date columns *only* from `ParameterMappings`; leave it NULL and the dashboard date picker is silently discarded and the `CALENDAR` join is dead weight. All three retrofitted datasets shipped NULL and had to be fixed. See `memory/feedback_date_filters_via_parametermappings.md`.
- **Any ratio card must keep numerator and denominator on the same coverage.** `SUM(PROFIT)` NULL-skips rows with no cost while `SUM(NET_VALUE)` counts them all, so an unguarded ratio understates margin (Oak & Vine read 63.7% instead of 82.9%). Add `AND F.AVG_NET_COST IS NOT NULL`. Note the £ figure was never wrong — `SUM` already skips NULLs — only the ratio was.
