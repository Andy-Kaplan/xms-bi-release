KNOWN GAP -- MargeBrutPurchasesBySupplier renders empty (NOT a Marge Brut defect):
  presentation.D_SUPPLIER on Gloucester holds only the CONVERT(BINARY(32), -999)
  'Unknown' sentinel, so all 2,438 F_PURCHASES_DAY lines fail the supplier join.
  Root cause: the "Supplier Dimension" PresentationControl step anchors its
  recursive CTE on "WHERE BOTTOM_LEVEL = 1 AND CURRENT_FLAG = 1" against
  datavault.SAT_SUPPLIER, but the Growyze "Growyze Suppliers" staging step never
  populates BOTTOM_LEVEL -- its four sibling dimension steps (Growyze Inventory
  Items, Growyze Location, Growyze Occasion, Growyze Product) all do. So
  SAT_SUPPLIER.BOTTOM_LEVEL is NULL on all 8 rows, the anchor matches nothing,
  and the dimension can only ever contain the sentinel. This affects EVERY
  Growyze org and any supplier-based reporting, not just this dashboard. Re-running
  the Supplier Dimension step does not help -- the fix must be upstream, in the
  Growyze staging step + SUPPLIER entity mapping, followed by a Growyze DV reload
  and then a D_SUPPLIER rebuild. Tracked as its own ledger item.

GOTCHAS LEARNED THIS SESSION (both cost real time):
  - core.DeployPresentationTables DROPs and recreates every registered
    presentation table for the target org. Do NOT use it to add one table to a
    populated org -- it would have wiped all 13 populated tables on Gloucester
    (F_LINEITEM_15MIN 1,464 rows, F_PURCHASES_DAY 2,438, D_INVITEM 502, ...).
    Create the single table from its registered ddl_script instead.
  - A Fact step's rebuild DELETE only spans MIN..MAX of the CURRENT result set.
    Narrowing a fact's key set therefore leaves orphan rows outside the new
    window; F_MARGEBRUT_MONTH kept 27 stale purchases-only rows until the table
    was truncated once.
