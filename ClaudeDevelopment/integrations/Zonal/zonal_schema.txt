Introduction

This document describes the table schema of the Dimensions SQL reporting database which is populated from the
AZTEC SQL operational database.
The Dimensions SQL Reporting Database is created and updated by the Dimensions Update program and is
designed to provide a simplified schema for reporting purposes.
The Dimensions Update runs on a scheduled basis, typically each morning following the completion of Site to Head
Office communications. The update process transfers the latest data from the AZTEC operational database into the
Dimensions reporting database to allow simplified and faster reporting.
The structure of this database is set to provide a set of summarised and fully detailed data for transactions that are
reported.
Each site is grouped into sales areas, which in turn hold terminals. Each site is in an area which in turn is in a
company which is then in an Estate, which is the top level
From the product side, the top level is defined as division. This is used as the reporting breakdown top level and
also to determine stock systems.
Under the Division there is a Sub Division, then Super Category, Category, Sub Category and finally Product.
Each product is defined as belonging to a single Sub Category with in turn automatically applies it to the hierarchy
above it.
Each customer transaction is stored as a unique terminal Account, with its own Account ID, and then each part of
the terminal account has a unique transaction ID.
The tables listed below are those that contain the data most frequently used by BI report writers to provide what is
required.
