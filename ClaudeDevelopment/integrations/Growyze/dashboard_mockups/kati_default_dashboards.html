Menu mix, item performance and margin trend

Growyze sales feed — granularity note

Growyze provides a product-level sales feed (DL_SALES order headers + DL_SALESDETAIL line items + DL_DISHES menu catalogue with salePrice + totalCost). This is sufficient for menu-item revenue, GP%, sold-quantity, mix, and category-level analysis. Limitations vs a true POS feed: no sub-product modifiers, no tender / discount breakdowns at line-item level, no per-second timestamps (line items carry the sale window OPEN_TIME/CLOSE_TIME from DL_SALES, not exact pour time). One blocker remains: P1 — F_LINEITEM_15MIN / F_PRODUCT_MARGIN_DAY currently filter IntegrationType = 'POS' and exclude Growyze.

Growyze data feeds — corrected understanding

Growyze provides both inventory and sales data, plus product cost from the menu catalogue:
  • Sales: DL_SALES (order headers — totalSales, OPEN/CLOSE time window) + DL_SALESDETAIL (line items — items_soldQty, items_totalValue, items_posId). Staged into GRYZ_LINEITEM at product-level granularity.
  • Menu / cost: DL_DISHES with salePrice + totalCost per dish. Profit / GP% therefore works without a separate recipe-ingest pipeline.
  • Inventory: stocktakes, deliveries, waste, transfers — handled by the StockEvent pipeline.
Caveats vs a true POS feed: no modifier-level lines, no tender/payment breakdown, no per-second timestamps (time comes from the sale window).

  6. Discounts series: if Kati's stakeholders want discount visibility, raise with Growyze — order-header net/gross delta is the best available proxy.
